Content Management Systems (CMS) typically fall into one of a few categories: ones like Wordpress and Drupal, which are feature rich, but complicated bits of software, site generators like Jekyll, which are geared to more technical users, or headless CMS systems, which have no UI and are also for technical users, but can have custom UIs to work with the APIs.

The purpose of the Omny CMS is to provide a site generator and a content UI build system. This is partly inspired by Tina CMS.  The purpose is to be able to provide all the benefits of a site generator, but with the ease of use of a purpose built UI. A major difference from Tina CMS is it was designed for serverless scenarios and to be able to run with minimal operational cost, and in fact no cost unless operating at high scale.

The key to this is leveraging existing tooling as much as possible. Currently GitHub is the primary way to use Omny CMS most efficiently. Site generation can be done via the Omny.Cms.Builder dotnet tool or package in GitHub actions. The UI uses plugins and optional configuration to be able to edit the content in the repo. This can work directly with GitHub APIs from the browser on a static site provided it can get configuration either via URL, minimal backend implementation, or GitHub authentication. With appropriate plugins the UI can be used for editing content that works with other site generators, like blog posts in Hexo.

An example using custom plugins is tntworld.ca, which has a custom book content type. The books have a title, cover image, one or more file links, and a description. They are sorted by release date and currently the most recent book is rendered by the Omny.Cms.Builder, followed by all the books from first to latest release date, into the single page site template.

This approach provides maximum flexibility. With sufficient plugins added and a way of managing them a hosted offering similar to Wordpress.com can be created, hiding all the technical details from users. For most interesting sites though the intent is that someone more technical would customize the experience and create an editing experience for less technical users.
